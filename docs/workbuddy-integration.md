# WorkBuddy 项目能力调研与接入

## 调研依据

2026-09-10 检查了用户提供的四张 WorkBuddy 5.2.6 截图、本地 `WorkbuddySkillGroups4DSH` 源码、转换脚本与许可证，以及以下官方文档：

- [WorkBuddy Overview](https://www.codebuddy.ai/docs/workbuddy/Overview)
- [Expert Center](https://www.codebuddy.ai/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Expert-Center)：专家具有领域职责和专用提示词，通过任务启用。
- [Automation](https://www.codebuddy.ai/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Automation-Guide)：一次性或周期调度，可配置执行目标和工作目录。

本地包 README 记载 45 个团队；实际读取到 **46 个顶层专家 bundle**。其中 147 个成员能够从结构化成员表匹配到真实角色文件。保留了原始 SOP、成员文件、脚本、参考资源和署名。少量资源的 YAML frontmatter 格式不合法，目录生成器保留全文并使用 Markdown 标题展示，不执行这些资源。

专家包提供领域内容，不包含 WorkBuddy 团队项目的服务端实现，也没有在本次资料中发现可直接复用的团队项目 API。本实现沿用 Team Hub 项目权限、PostgreSQL 和原生 AgentTeams，以本地专家定义提供专业能力。

## 已实现

| WorkBuddy 视图 | Team Hub 实现 |
| --- | --- |
| 动态 | 项目审计动态流、成员名称、时间、仅看我的动态 |
| 计划 | 待开始、进行中、暂停、完成四列看板；窄屏纵向排列；负责人、截止时间、搜索、状态修改 |
| 任务 | 项目任务列表，按创建者、负责人、个人或协同任务过滤；个人任务只对创建者可见 |
| 资产 | 项目目录、新建文件夹、文件上传下载、删除、容量统计；执行结果自动回流 |
| 指令 | 项目经理、技术总监编辑项目背景与规范，保存时校验版本避免覆盖其他人的更新 |
| 专家 | 搜索 46 个专家团、选择成员加入项目，重复导入更新定义而不重复创建 |
| 技能 | 选择项目启用的专家 SOP，服务器通过原生 skill-filesystem 发现；角色文件保留原路径 |
| 连接器 | 使用现有 GitLab HTTP/HTTPS 多仓库连接配置、分支、加密访问令牌 |
| 自动化 | 项目经理、技术总监配置首次时间和周期，暂停、恢复、删除；服务器常驻调度 |

普通项目成员可以创建共享待办或个人待办、上传共享资产。创建者、负责人和项目管理者可以编辑共享任务；即使是项目管理者也不能读取其他人的个人待办。个人任务必须先改为共享，才可交给项目 Agent，防止其内容通过共享执行记录泄露。

## 专家与执行

在“项目工作台 → 配置”搜索专家团并选择成员“加入项目”。有成员表的专家团展示已映射成员；没有可可靠映射成员表的专家团默认选择主理人，也可手动选择其角色资源作为成员。单次最多 16 位，超过时需要缩小参与范围。

随后在计划中创建共享待办，点击“交给 Agent”，选择成员和仓库。原生 AgentTeams 生成计划，手动任务批准后执行。专家原文中的 `TeamCreate`、`Agent`、`SendMessage` 等 WorkBuddy 调度指令由适配提示明确映射到现有 AgentTeams 调度，不安装或冒充 WorkBuddy 私有运行时。专业 SOP 原文完整保留；对依赖外部网站、工具、付费服务的专家，仍需相应能力与网络条件。

任务创建时保存项目指令、参与成员与仓库定义，并把共享资产内容复制到任务快照。执行器将资产放在 `/control/assets/<资产ID>`，原名称记入任务上下文；专家资源位于 `/control/skills/<bundle>`。两者只读挂载，成果写入 `/workspace/deliverables`。已经创建的任务不会因项目指令或资产删除而改变上下文。

执行结束后，文本结果报告与符合容量限制的交付文件进入项目资产。成功任务关联的待办自动完成；失败或取消后变为暂停。代码仓库仍保留在服务器任务卷，不自动推送、合并或部署。

这些项目指令和专家职责仅传入相应的服务器任务，**不会注入 Desktop 普通新会话**。项目会话同步和显式复用仍保持原有行为。

## 自动化

首次时间以浏览器本地时间输入，服务端存储为 UTC；周期为 5–10080 分钟。创建时必须勾选“允许到期后自动批准并执行任务”。到期后保存一条独立任务并通过原生计划批准流程执行，关闭 Desktop 不影响调度。

同一自动化的上次任务尚未结束时不叠加启动；数据库事务避免重复入队。服务中断期间错过的周期恢复后执行一次，不补发全部历史周期。创建者失去项目管理权限、账号停用或选择资源失效时暂停并记录错误。暂停自动化停止后续调度，已经启动的任务须在 Agent 协作页停止。

## 部署与维护

插件版本：`0.1.0-alpha.10`。服务仍使用内网 HTTP，监听 `0.0.0.0:3090`。升级前备份 PostgreSQL，然后：

```sh
docker compose -p dsh-team --env-file .env.team -f compose.team.yml --profile agents build
docker compose -p dsh-team --env-file .env.team -f compose.team.yml --profile agents up -d
```

专家定义已随服务打包在 `src/team/expert-pack`，运行不依赖开发机的相邻目录。更新本地专家源后运行 `node scripts/import-workbuddy.mjs ../WorkbuddySkillGroups4DSH`，审核目录变化，再重建服务镜像。许可证位于专家目录的 `LICENSE`。

## 范围与限制

- 文件单个最大 5 MB，每项目累计 100 MB、最多 1000 项；目录删除前必须为空。上传文件作为资产供模型读取，不自动解析 PDF/OCR，也不自动执行上传脚本。
- 每次执行最多回流 20 个成果文件、总计 20 MB，目录深度最多 4 层，跳过符号链接、隐藏文件和超限文件。完整工作目录仍保留在任务卷，超限成果可由管理员导出。
- 任务列表首版最多读取 500 项、动态最近 100 条；未实现拖拽排序、批量操作、评论与通知、资产在线编辑及日历式复杂调度。
- 连接器目前是 GitLab，多种外部 MCP/企业消息服务尚未实现。没有连接或同步 WorkBuddy 账号、云项目及其私有 API。
- Mac、Docker 必须保持运行；Docker 引擎或服务器重启后的进行中模型任务不自动续跑。执行管理服务重启可接管仍在运行的容器。
- 已验证真实 PostgreSQL 权限与并发、浏览器操作、原生 Harness/AgentTeams 自动执行、专家与资产只读挂载。验证模型为确定性测试服务；46 个专家团各自的真实模型产出质量以及打包 Electron 安装仍需业务验收。
